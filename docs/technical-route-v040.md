# v0.4 任务状态新鲜度实验路线

本实验保持课题《受限环境下的语义自适应视频传输系统设计与实现》，不接入设备控制，不使用手机热点，不修改已部署的 8088 服务。新服务以独立容器和端口 8089 只读旧采集发布的最新共享帧，手机与树莓派处于同一可信局域网时可打开页面。默认合成输入仅用于程序验证；真实摄像头成绩必须另测。

## 研究问题与技术增量

现有 v0.3 将权重、局部变化和高质量刷新等待时间用于选择 JPEG 重点块，但只在整帧收齐后绘制，整帧一次确认。v0.4 首先检验更细的闭环：低分辨率全景先显示，重点块只在相同帧号且未超过 80 ms 本地补齐期限时叠加；发送端仅以浏览器确实绘制的重点块更新该区域的清晰刷新时刻。每帧至多一个重点块，避免不受控积压。区域排序考虑人工任务权重、局部变化、上次确认显示后的时间和上次块字节成本。

客户端的清晰显示时间取 Canvas 绘制后的本地单调时钟；发送端无法直接读取这个时钟，排序中的“上次确认显示时间”实际采用**显示确认抵达树莓派的时刻**作为保守代理。它包含反馈链路延迟，不能作为精确的手机绘制时刻，也不能直接拿来计算光学端到端延迟。

这不是新的神经语义编解码方法。任务区域/质量分配、年龄相关指标和部分可靠传输均已有研究；本文可主张的是**在该硬件和受限链路上的可复核工程组合、移动接收端确认语义和失效边界**，而非相关基本概念的首创。

## 两阶段实现

1. **本里程碑：** 复用旧采集只读边界，使用独立 WebSocket/TCP 实验版验证任务排序、同源帧渐进绘制和手机端测量。TCP 队头阻塞仍存在；这一步不能称为协议层超低延迟改造。
2. **下一里程碑：** 在相同 JPEG、任务区域、目标节奏和接收端上，加入成熟 WebRTC DataChannel 实现并比较期限发送。需要有界分片、发送缓冲限制、到期淘汰与失包统计；只有对照证据支持时才考虑切换主传输。H.264 原生视频轨道可作进一步对照，但应计入树莓派 5 软件编码及 USB MJPEG 输入的转码成本。

## 验证口径

- 对照：v0.3 整帧 WebSocket、v0.4 分层 WebSocket、旧版 JPEG DataChannel；后续另测原生 H.264 WebRTC。不同协议须使用相同输入片段、目标帧率、有效载荷预算和网络轨迹。不能拿不同场景/速率的现场运行结果作协议因果结论。
- 手机端记录实际 Canvas 显示事件：全景首次可见时间、重点块完成率和每个区域最后确认清晰显示时间。帧龄超过 250 ms、校时未知、断流时间都不能算作新鲜收益；同时记录 P50/P95、最长无新帧间隔和客户端重连次数。
- 任务评价需独立人工真值，例如两处可见状态改变的时间与辨识结果。合成标记仅为代理任务，不代表工业故障诊断。曝光到屏幕发光需要独立光学实验，不能用当前软件时间戳代替。
- 当前无线客户端间已有秒级往返和长时间冻结。独立服务应证明在可通信区间减少过时/无关字节；不能声称消除接入点或无线链路的失联。

## 研究依据与边界

- [AccMPEG, MLSys 2022](https://proceedings.mlsys.org/paper_files/paper/2022/file/853f7b3615411c82a2ae439ab8c4c96e-Paper.pdf)：任务重要性驱动编码的先例，不将区域优先本身表述为本文原创。
- [Age of Semantic Information-Aware Wireless Transmission, 2025 preprint](https://arxiv.org/abs/2508.12248)：语义重要性和信息时效联合评价的研究背景；本文不采用该文的 MIMO 优化模型。
- [RFC 8831](https://www.rfc-editor.org/rfc/rfc8831.html)：WebRTC DataChannel 的无序和部分可靠传输能力；本里程碑尚未使用。
- [Syntra, NSDI 2026](https://www.usenix.org/conference/nsdi26/presentation/pan)：跨码率、跳帧、拥塞和冗余的联合控制方向；本文目前仅实现轻量启发式排序。
- [Law, NSDI 2026](https://www.usenix.org/conference/nsdi26/presentation/shen-yibin)：Wi-Fi 链路层排队造成长尾的证据，说明应用层新鲜度优化不能保证任意无线条件下的超低延迟。
- [Raspberry Pi 5 H.264 encoding study](https://pip-assets.raspberrypi.com/categories/685-app-notes-guides-whitepapers/documents/RP-010033-WP-1-H.264%20encoding%20performance%20on%20Raspberry%20Pi%205_series%20computers.pdf)：树莓派 5 使用软件 H.264 编码；论文报告的性能不能直接替代本项目 USB MJPEG 路径实测。

远程页面仍是无身份认证的可信局域网实验原型，不可直接暴露公网。AI 只作为离线任务区域建议的后续候选，不进入本里程碑逐帧关键路径。
