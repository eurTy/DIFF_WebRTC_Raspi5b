# 2026-10-10 低延迟双通道更新

## 已部署

- 保持 USB 摄像头原生 MJPEG、1280x720、30fps 采集和锐度 4；不重新编码 JPEG。
- 新增 WebSocket 最新帧通道：浏览器解码完成后请求下一帧，服务端从共享内存读取最新完整帧，每连接最多一帧在途，跳过未发送的旧采集帧。
- 保留 WebRTC DataChannel 默认入口，在网页顶部可切换 WebRTC / WebSocket。
- 用可选 Compose 配置让采集容器、网关容器和普通用户运行的信令服务访问同一份宿主机共享内存。
- 修复采集重启后的旧帧污染、画面年龄高亮，以及新 viewer 重复使用旧 WebRTC offer 的问题；网关会话失效时由容器监督器重启。
- 树莓派运行服务和两个容器均正常；Pi Wi-Fi 省电关闭，临时 BSSID 锁定尝试已回退。

## 测试结果

延迟边界为 JPEG 写入共享内存到浏览器 `img.decode()` 完成，不包含曝光、摄像头内部编码和显示刷新。测试先后进行，Wi-Fi 状态不完全相同，不能把结果视为严格受控的协议对照。

| 2026-10-10 测试 | 时长 | 平均延迟 | P95 | 实际显示帧率 |
| --- | ---: | ---: | ---: | ---: |
| WebRTC | 120 秒 | 244.6 ms | 592.8 ms | 26.8 fps |
| WebSocket 最新帧 | 180 秒 | 42.8 ms | 87.3 ms | 23.5 fps |

新通道这轮最长单帧延迟约 151.9 ms；实际显示帧率较低是跳过旧帧的代价，不代表降低采集分辨率或单帧 JPEG 画质。29 项 Node 测试、连续通道切换、断线重连、桌面与手机宽度布局以及非空白 1280x720 图像检查通过。

## 访问与限制

- 新通道：`http://192.168.3.19:8080/?transport=ws`
- 原通道：`http://192.168.3.19:8080/?transport=webrtc`
- 两种通道当前均只支持单 viewer。WebSocket 运行在 TCP 上，Wi-Fi 中断或重传时仍会卡顿；`http/ws` 仅用于可信局域网测试。
